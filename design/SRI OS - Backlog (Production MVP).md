# SRI OS — Backlog สำหรับ Production MVP (ส่งต่อ Claude Code)

> บันทึกจาก review วันที่ 17/09/2026 · prototype ปัจจุบันคือ `SRI OS.dc.html` (ยังเป็น mock ไม่ต้องแก้ตอนนี้)

## 1. หมวดย่อยของการบันทึกรายการยัง "ไม่เป็น Logic"
ปัญหา: ตอนนี้ประเภทรายการกับหมวดย่อยแยกจากกันแบบหลวมๆ ทำให้บันทึกผิดหมวดได้

- การกู้เงินเพิ่ม → ต้องลงหมวด **กู้เงิน (จัดหาเงิน)** ห้ามเป็น **รายได้** เงินเข้าบัญชีแต่ไม่ใช่รายได้
- ต้องบังคับความสัมพันธ์: ประเภทรายการ → หมวดย่อยที่อนุญาต → ผลกระทบต่องบ (P&L / งบดุล / กระแสเงินสด) เป็นตารางกฎเดียวที่ระบบอ้างอิง ไม่ใช่ dropdown อิสระ

## 2. รายการกู้เงิน / ให้กู้ ต้องมีหน้าต่างกรอกเงื่อนไข
เมื่อเลือกประเภท "กู้/เพิ่มทุน" หรือ "ให้กู้" ต้องเปิดฟอร์มเงื่อนไขสัญญา:

- ยืมจากใคร / ให้ใครยืม (ผูก contact)
- วงเงิน · วันที่รับเงิน
- กำหนดคืน (วันครบกำหนด หรือ งวดผ่อน)
- อัตราดอกเบี้ย · วิธีคิดดอกเบี้ย · วันชำระดอกแต่ละงวด
- หลักประกัน (ถ้ามี) · เอกสารสัญญาแนบ

ระบบต้องสร้างตารางงวดชำระ (schedule) จากเงื่อนไขนี้ เพื่อให้หน้า "ยืนยันรับ-จ่าย" และ "ค้างรับ/ค้างจ่าย" ดึงไปใช้ได้อัตโนมัติ

## 3. Contact ต้องสร้างได้จากในฟอร์ม (inline create + กลับมาที่เดิม)
ถ้ายังไม่มี contact คนนั้นในระบบ ต้องกดสร้างจากในฟอร์มได้เลย กรอก:

- ชื่อ · นามสกุล
- เบอร์โทร
- LINE ID
- อีเมล

บันทึกแล้ว **ต้องเด้งกลับมาที่ฟอร์มเดิม พร้อมเลือก contact นั้นไว้ให้แล้ว** (ห้ามให้กรอกฟอร์มรายการใหม่ทั้งหมด)

## 4. ขายทรัพย์ / ขายเงินลงทุน ต้องคำนวณ Cap Gain/Loss ให้อัตโนมัติ
เมื่อบันทึก "ลงทุน (ขาย/รับคืน)":

- ดึงต้นทุนของทรัพย์ชิ้นนั้นมาเทียบกับราคาขายจริง
- คำนวณ **กำไร/ขาดทุนจากการขาย (Capital Gain/Loss)** ให้เห็นในฟอร์มก่อนยืนยัน (ให้แก้ค่าธรรมเนียม/ค่าใช้จ่ายในการขายได้)
- ลงบัญชีสองด้านให้ถูก: ตัดทรัพย์ออกจากงบดุลตามต้นทุน + รับรู้กำไร/ขาดทุนใน P&L + เงินเข้าเป็นกระแสเงินสดจากการลงทุน
- กำไรยังไม่รับรู้ (unrealized) ของทรัพย์ชิ้นนั้นต้องถูกล้างออกพร้อมกัน

## 5. คืนเงินกู้ / จ่ายผลตอบแทน ต้องแยกเงินต้นกับดอกเบี้ยตาม Logic
เมื่อบันทึก "คืนเงินกู้/จ่ายผลตอบแทน":

- แยกอัตโนมัติเป็น **เงินต้น** (ลดหนี้สินในงบดุล ไม่ใช่ค่าใช้จ่าย) กับ **ดอกเบี้ย** (เป็นค่าใช้จ่ายใน P&L)
- ดึงยอดคงเหลือและงวดที่ค้างจากสัญญาในข้อ 2 มาตั้งค่าให้ แล้วให้ผู้ใช้ยืนยัน/แก้ได้
- เงินปันผลจ่ายต้องลงเป็นการลดส่วนของเจ้าของ ไม่ใช่ค่าใช้จ่าย
