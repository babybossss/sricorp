# SRI OS — Company OS ของ SRI Corporation

ระบบ ERP / Company OS สำหรับ Family Office ไทย ดูแลเงินทั้งฝั่งบริษัทและบุคคลในครอบครัว
ในที่เดียว โดยมองทุกอย่างเป็น **กองกลางของ SRI Family** — ทรัพย์บางตัวแค่อยู่ในชื่อบุคคลเท่านั้น

> รอบนี้เป็น **UI + mock data** ยังไม่ต่อ Supabase ข้อมูลทั้งหมดอยู่ในหน่วยความจำ รีเฟรชแล้วกลับค่าเริ่มต้น

## Stack

Next.js 15 (App Router) · TypeScript · Tailwind CSS · shadcn/ui (Radix) · zustand

## เริ่มใช้งาน

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # production build
npm run typecheck
```

## งานจาก backlog ที่ทำในรอบนี้

### ข้อ 1 — ตารางกฎหมวดย่อย

`src/lib/rules/tx-rules.ts` คือ **ตารางกฎเดียว** ที่ทั้งระบบอ้างอิง ผูก

```
ประเภทรายการ → หมวดย่อยที่อนุญาต → ผลกระทบต่องบ (P&L / งบดุล / กระแสเงินสด)
```

ผลที่ได้:

- หมวดย่อยในฟอร์มไม่ใช่ dropdown อิสระอีกต่อไป — มาจากประเภทที่เลือกเท่านั้น
- **กู้เงินเพิ่ม** อยู่ใต้ `กู้/เพิ่มทุน` เลือกจาก `รายได้` ไม่ได้ เพราะเงินเข้าบัญชีแต่ไม่ใช่รายได้
- เปลี่ยนประเภทแล้วหมวดย่อยรีเซ็ตมาอยู่ในชุดที่ถูกต้องเสมอ ไม่ค้างค่าข้ามประเภท
- ฟอร์มแสดง **ผลกระทบต่องบ** ให้เห็นก่อนกดยืนยัน พร้อมคำเตือนของหมวดที่ลงผิดง่าย
- ดูตารางกฎทั้งหมดได้ที่ `ตั้งค่า › ผังบัญชี & ประเภทรายการ`

ข้อ 2 · 4 · 5 ของ backlog ผูกไว้กับตารางนี้แล้วผ่านฟิลด์ `requires`
(`loanTerms`, `capitalGain`, `principalInterestSplit`) — ฟอร์มรู้แล้วว่าต้องเปิดหน้าต่างไหน
ส่วนตัวหน้าต่างกรอกเงื่อนไขจะทำรอบถัดไป

### ข้อ 3 — สร้าง contact จากในฟอร์ม

`src/components/form/contact-picker.tsx` — ปุ่ม **＋ สร้างผู้ติดต่อใหม่** เปิด dialog ซ้อนอีกชั้น
กรอก ชื่อ · นามสกุล · เบอร์โทร · LINE ID · อีเมล แล้วกดบันทึก ระบบจะ:

1. เพิ่มผู้ติดต่อเข้า store
2. **เลือกคนนั้นไว้ในฟอร์มเดิมให้แล้ว**
3. ปิดเฉพาะ dialog ลูก — ฟอร์มรายการยังเปิดค้างพร้อมค่าที่กรอกไว้ทุกช่อง

ผู้ใช้จึงไม่ต้องกรอกฟอร์มรายการใหม่ทั้งหมด ใช้ได้ทั้ง desktop modal, mobile stepper
และหน้า Asset Detail › ข้อมูลสัญญา

## ข้อกำหนดด้านการเข้าถึง

ผู้ใช้มีผู้สูงอายุ ทุกหน้าจึงยึด:

- ตัวอักษรเล็กสุด 16px · ตัวปกติ 18px · มี **โหมดตัวใหญ่ +2px** สลับได้ที่ท้าย sidebar
- ปุ่มสูงไม่ต่ำกว่า 52px (มือถือ 56px) และ **มีข้อความกำกับเสมอ** ไม่ใช้ปุ่มไอคอนเดี่ยว
- คอนทราสต์สูง · วงแหวนโฟกัสหนา 3px
- ตัวเลขใช้ tabular numbers ทั้งระบบ · ติดลบใช้วงเล็บ

## จะต่อ Supabase ต่ออย่างไร

`src/lib/store.ts` และ `src/lib/mock/*` คือขอบเขตที่ต้องเปลี่ยน — shape ของข้อมูล
ออกแบบไว้ให้ตรงกับตารางจริงแล้ว ส่วน `tx-rules.ts` ควรอยู่ในโค้ดต่อไป (หรือ sync เป็น
seed ของตาราง reference) เพราะเป็นกฎบัญชี ไม่ใช่ข้อมูลผู้ใช้
