ทุกข้อ **ย้อนกลับได้** ถ้าลูกพี่ไม่เห็นด้วย บอกได้เลย

## 2026-09-17

### D-001 · Supabase region = Singapore (ap-southeast-1)
**ทางเลือก**: Tokyo (ap-northeast-1) ตาม project เดิมของลูกพี่ vs Singapore ตามที่ PLAN.md แนะนำ
**เลือก**: Singapore
**เหตุผล**: ผู้ใช้ทั้งหมดอยู่ไทย latency ต่ำกว่า Tokyo และตรงกับที่ระบุไว้ใน PLAN.md หัวข้อ 12.1
**ย้อนกลับ**: ต้องสร้าง project ใหม่แล้ว migrate — ควรยืนยันก่อนลงข้อมูลจริง

### D-002 · ยังไม่สร้าง Supabase project (ติด free tier limit)
**สถานะ**: ⛔ ต้องลูกพี่ action
**สาเหตุ**: org `thanakorns` มี active project ครบ 2 แล้ว (`hermes database`, `thanakorns`) — free tier จำกัด 2
**ทางเลือกที่ลูกพี่ต้องเลือก**:
1. Pause project ที่ไม่ได้ใช้ (ฟรี แต่ project นั้นจะหยุด)
2. Upgrade org เป็น Pro (มีค่าใช้จ่ายรายเดือน — ดูราคาปัจจุบันก่อนกด)
3. ใช้ project `thanakorns` เดิม แล้วแยกด้วย schema `sri_os` (ไม่มีค่าใช้จ่ายเพิ่ม แต่ปนกับข้อมูลเดิม)
**ผมไม่ตัดสินใจเอง** เพราะ pause database ตัวอื่นกระทบงานอื่นของลูกพี่ และ upgrade คือเงินจริง
**ผลกระทบตอนนี้**: ไม่มี — งานคืนนี้เตรียม migration SQL ไว้ ยังไม่ต้อง apply

### D-003 · ย้าย SRI_OS_MVP_Plan.md → docs/PLAN.md
**เหตุผล**: PLAN.md เองระบุว่า "วางไฟล์นี้เป็น docs/PLAN.md ใน repo" และ agent ทุกตัวอ้างถึง path นี้
**ย้อนกลับ**: `git mv` กลับได้ทันที

### D-004 · ตารางกฎอยู่ในโค้ด ไม่ใช่แค่ในตาราง config
**ทางเลือก**: เก็บ `txn_types` ในตาราง DB อย่างเดียว vs เก็บใน TypeScript ด้วย
**เลือก**: `src/lib/rules/tx-rules.ts` เป็นแหล่งความจริง แล้ว seed ลง DB
**เหตุผล**: กฎบัญชีไม่ใช่ข้อมูลผู้ใช้ — ต้อง review ผ่าน PR และ test ได้ ถ้าอยู่ใน DB อย่างเดียวจะแก้ได้โดยไม่มีใครตรวจ
ส่วนที่ผู้ใช้ตั้งค่าได้จริง (เปิด/ปิดหมวด, ชื่อที่แสดง) ยังอยู่ใน DB ตามกฎเหล็กข้อ 5
**ย้อนกลับ**: ได้ แต่ต้องย้าย test ตามไปด้วย

### D-005 · ลำดับบัญชีธนาคารและสถานะเปิด/ปิด เก็บใน store ฝั่ง client (ชั่วคราว)
**เหตุผล**: รอบนี้ยังไม่มี DB — `src/lib/store.ts` จำลอง `bank_accounts.sort_order` และ `is_active`
**ย้อนกลับ**: ตอนต่อ Supabase ให้ย้ายไปตาราง `bank_accounts` shape เดิมใช้ได้เลย
