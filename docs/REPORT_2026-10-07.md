## 1. เสร็จแล้ว

### ก. เครื่องยนต์บัญชีเลิกพึ่งข้อมูลจำลอง
เดิมเครื่องยนต์ที่คำนวณคู่บัญชีอ่านรายชื่อผู้ถือและบัญชีธนาคารจากข้อมูลตัวอย่าง
ที่เราใส่ไว้ตอนทำหน้าจอ ตอนนี้มันรับข้อมูลจากข้างนอกเข้าไป
แปลว่าพอต่อ Supabase จริง เปลี่ยนแค่ 2 บรรทัด

**สิ่งที่ทำให้ผมมั่นใจว่าตัวเลขไม่เปลี่ยน**: ผู้ตรวจรัน **15,007 เคส**
เทียบกับโค้ดก่อนแก้ ทุกหมวดย่อย × 5 ผู้ถือ × 7 บัญชี × ทุกเงื่อนไข
ต่างกันจุดเดียวคือข้อความ error ตอนเจอผู้ถือที่ไม่รู้จัก ซึ่งดีขึ้น

### ข. ล็อกอินจริงและกั้นหน้าตามตำแหน่ง
เดิม **ทุกหน้าเปิดดูได้โดยไม่ต้องล็อกอิน** และปุ่ม "ส่งลิงก์เข้าอีเมล"
กดแล้วเข้าระบบได้เลยโดยไม่ต้องยืนยันตัวตนอะไรเลย

ตอนนี้: Google OAuth จริง · ทุกหน้าถามสิทธิ์จาก DB ก่อนแสดง ·
เมนูที่ไม่มีสิทธิ์ถูกซ่อน · ปุ่มอีเมลปิดไว้และเขียนว่า "(เร็วๆ นี้)"
แทนที่จะปล่อยเป็นทางเข้าที่ไม่ต้องล็อกอิน

ตามที่ลูกพี่สั่ง: **Manager ดูภาพรวมการลงทุนไม่ได้** เห็นแค่ทรัพย์ที่ตนบริหาร ·
**Staff ลงข้อมูลได้เท่านั้น**

ข้อความที่ลูกพี่สั่งไว้อยู่ครบ — ปุ่ม "เข้าสู่ระบบด้วย Google" ·
"Sustainable Generational Wealth and Happiness" · "Designed by Mr. LU"

### ค. ต้นทุนแบบ FIFO
สำหรับหุ้น ทองคำ คริปโต ที่ซื้อหลายครั้งราคาต่างกัน เวลาขายต้องรู้ว่า
ขายล็อตไหนออกไปเพื่อคิดกำไรให้ถูก

ผู้ตรวจรันสุ่ม 200,000 เคส ยืนยันว่าเศษสตางค์ไม่หายไม่งอก
และ 100,000 การสลับลำดับข้อมูลให้ผลเดียวกันทุกครั้ง

**เจอรูหนึ่งจุดและปิดแล้ว**: จำนวนที่เล็กมากๆ (เช่น 0.00000000001 หน่วย)
ถูกปัดเป็นศูนย์เงียบๆ ทำให้ **ขายได้เงินมาเต็มจำนวนโดยต้นทุนเป็น 0
= กำไรเกินจริงทั้งก้อน** และล็อตเศษธุลีจะหายจากสมุดพร้อมต้นทุนของมัน
ตอนนี้ปฏิเสธ ไม่ปัด

## 2. ติดอยู่ — สิทธิ์ตามตำแหน่งใน DB

ชิ้นนี้ถูก **ตีกลับ 3 รอบ** และยังไม่ผ่าน กำลังแก้รอบที่ 4

ผมตั้งใจให้ตรวจหนักเพราะมันคือชั้นที่กั้นว่าใครเห็นเงินใครได้ ถ้าชิ้นนี้ผิด
การกั้นหน้าจอข้างบนไม่มีความหมายเลย

ตัวอย่างรูที่ถูกจับได้ (ทุกข้อพิสูจน์ด้วยการรันจริง ไม่ใช่อ่านโค้ดเดา):
- **Manager ย้ายบรรทัดบัญชีออกจากรายการที่ปิดแล้วได้** ทำให้รายการเหลือ
  เดบิต 2,000 เครดิต 0 แล้วบันทึกผ่าน — งบไม่สมดุลแบบที่ไม่มีใครเห็น
- **ย้ายรายการของบุคคลเข้าสมุดนิติบุคคลได้** โดยไม่มีไฟล์หลักฐาน
  ไม่มีคู่ค้า และไม่มีขาที่สอง
- **Manager รวมยอดสัญญาทั้ง 10,000,000 ได้** ทั้งที่ควรเห็นแค่ของตัวเอง
- **ตารางสรุปมูลค่าทรัพย์ไม่เคารพสิทธิ์** ใครเปิดก็เห็นมูลค่าทั้งพอร์ต

**เรื่องที่ต้องบอกตรงๆ**: บางข้อผ่านเทสต์ของคนแก้มาแล้ว แต่เทสต์นั้น
ไม่ได้ครอบเส้นทางที่รูอยู่จริง เทสต์เขียวพิสูจน์ได้แค่กฎที่ตัวมันเขียนไว้
คืนนี้เจอเรื่องนี้ซ้ำสองครั้ง

## 3. สิ่งที่พบใน DB จริง — ต้องปิดก่อนเปิดให้ใครใช้

### ช่องโหว่ 3 จุดที่อยู่ใน DB จริงตอนนี้

1. **ยกเลิกรายการแล้วเอากลับมาได้** ขณะที่รายการกลับรายการยังอยู่
   → **รายได้ถูกนับสองครั้ง** (เทสต์ได้เดบิต 1,400 แทน 700) ตำแหน่ง Management ทำได้
2. **กติกาหลักฐานของนิติบุคคลหลบได้** แค่ติดป้ายว่าเป็น "รายการกลับรายการ"
   โดยไม่ต้องชี้ว่ากลับรายการอะไร → บันทึก 5,000,000 โดยไม่มีหลักฐานเลย
3. **กติกาหลักฐานตรวจแค่ตอนสร้างรายการใหม่** ไม่ตรวจตอนแก้
   → สร้างร่างพร้อมแนบไฟล์ → ลบไฟล์ออก → เปลี่ยนเป็นบันทึกแล้ว ผ่านทุกด่าน
   ซึ่งเป็นวิธีทำงานปกติของคิวอนุมัติพอดี

**ความเสี่ยงจริงตอนนี้เป็นศูนย์** เพราะยังไม่มีบัญชีผู้ใช้อื่นนอกจากลูกพี่
และหน้าจอยังเขียนลง DB ไม่ได้ แต่ทั้งสามข้อต้องปิดก่อนสร้างบัญชีให้ใคร

### ไฟล์กับ DB จริงไม่ตรงกัน

ผมเช็คแล้วพบว่า **DB จริงตามหลังโค้ดในรีโปอยู่หลายก้าว**:

| สิ่งที่อยู่ในรีโป | อยู่ใน DB จริงไหม |
|---|---|
| บัญชี `1220 ลูกหนี้อื่น` | **ไม่มี** |
| คอลัมน์ที่ใช้ตั้งค้างรับ-ค้างจ่าย | **ไม่มี** |
| ตารางสิทธิ์ตามตำแหน่ง | **ไม่มี** |
| ผังบัญชี | รีโป 51 รหัส · DB จริง 47 |

แปลว่า **งานกติกาตั้งค้างรับ-ค้างจ่ายทั้งหมดยังไม่ขึ้น DB จริง** มีแต่ในไฟล์

และยังมี **policy 10 ตัวที่อยู่ใน DB จริงแต่ไม่มีไฟล์ที่สร้างมัน** —
ผมเคยใส่ด้วยมือตอนทำงานวันก่อนๆ ถ้าวันหนึ่งต้องสร้าง DB ใหม่จากไฟล์
policy พวกนี้จะหายไปเงียบๆ

ผมยังไม่ apply อะไรลง DB จริงคืนนี้ ตามที่บอกไว้ว่าจะไม่ทำโดยไม่บอกลูกพี่ก่อน

### เรื่องใหญ่ที่เพิ่งพบ — แอปคุยกับ DB ไม่ได้เลยตอนนี้

ผมไล่สิทธิ์ใน DB จริงแล้วพบว่า **ไม่มีการให้สิทธิ์อะไรเลย** กับผู้ใช้ที่ล็อกอินเข้ามา
มีแต่บัญชีเจ้าของฐานข้อมูลที่เข้าถึงได้

แปลว่าถ้าลูกพี่ล็อกอินเข้าระบบตอนนี้ **ทุกหน้าจะอ่านข้อมูลไม่ได้** เพราะถูกปฏิเสธ
ตั้งแต่ประตูแรก ก่อนจะถึงชั้นที่กรองว่าใครเห็นแถวไหนด้วยซ้ำ

**ข่าวดี**: ช่องโหว่ 3 จุดข้างบน **เข้าไม่ถึงจากแอปเลย** เพราะไม่มีใครมีสิทธิ์
แตะตารางพวกนั้นได้ตั้งแต่ต้น ความเสี่ยงเป็นศูนย์จริงๆ ไม่ใช่แค่ "ยังไม่มีบัญชีใคร"

**ข่าวร้าย**: ต้องเปิดสิทธิ์ก่อน ปุ่มบันทึกจึงจะเขียนลง DB ได้
ผมกำลังเขียนเป็นไฟล์ migration ที่ให้สิทธิ์**ขั้นต่ำเท่าที่จำเป็น** —
อ่าน/เพิ่ม/แก้/ลบ ได้ แต่ **ไม่ให้สิทธิ์ล้างตารางทั้งใบ** และไม่ให้สิทธิ์
ผู้ใช้ที่ยังไม่ล็อกอินเลย

และผมให้เครื่องมือทดสอบ **ใช้ไฟล์เดียวกันกับที่จะ apply ขึ้นของจริง**
ไม่ใช่ตั้งสิทธิ์เองแยกกัน — นี่คือการปิดต้นตอของปัญหาข้างล่าง ไม่ใช่แค่แก้ตัวเลข

### เครื่องมือทดสอบของเราเองหลวมกว่าของจริง
`scripts/test-rls-local.sh` ให้สิทธิ์ `grant all` ซึ่งกว้างกว่า DB จริง
ทำให้ผู้ตรวจรายงานช่องโหว่หนึ่งข้อที่ **ไม่มีจริงใน production**
ผมเช็คเองแล้วว่าไม่มี กำลังแก้ให้เครื่องมือตรงกับของจริง
ไม่งั้นเทสต์ทุกตัวที่ผ่านก็เชื่อไม่ได้เต็มร้อย

## 4. คำถามที่รอลูกพี่ตัดสินใจ

เรียงตามความด่วน

### ด่วน — ติดงานอยู่
1. **จะให้ผม apply migration ลง Supabase จริงไหม** และเมื่อไหร่
   ตอนนี้ของใหม่ทั้งหมดค้างอยู่ในไฟล์ ยังไม่ขึ้น DB จริง
   ผมแนะนำว่า **รอให้ชิ้นสิทธิ์ผ่านตรวจก่อน** แล้ว apply ทีเดียวพร้อมกัน
2. **รายชื่อคนที่จะใช้ระบบ + อีเมล Google + ตำแหน่ง**
   ยังสร้างบัญชีให้ใครไม่ได้จนได้ข้อมูลนี้ และ **ยังไม่ควรสร้างบัญชี Staff
   จนปิดช่องโหว่ข้อ 3 เสร็จ**
3. **เปิด Google provider ใน Supabase แล้วหรือยัง** และ **key ของ Google Maps
   ใส่ใน Vercel แล้วหรือยัง** — ผมอ่านค่าใน Vercel ด้วยสิทธิ์ของผมไม่ได้
   (ขึ้น 404) ลูกพี่เปิดหน้าทรัพย์สิน → แท็บแผนที่ ถ้าเห็นแผนที่ดาวเทียมคือได้แล้ว
   ถ้าขึ้นข้อความบอกวิธีตั้งค่าคือยังไม่ได้

### ยืนยันการตีความ
4. **เงินมัดจำผู้เช่า** — เอกสารเก่าเขียนว่าเป็นการจัดหาเงินทุน
   แต่ตารางกฎลงเป็นการดำเนินงาน ผมตัดสินว่า **ตารางกฎถูก**
   เพราะมัดจำผูกกับการให้เช่า ไม่ใช่การกู้เงิน แก้เอกสารตามแล้ว
   แต่อันนี้เป็นการตีความ ไม่ใช่กฎที่มีคำตอบเดียว **ขอให้ลูกพี่ยืนยัน**
5. **จะมีการตีราคาทรัพย์ใหม่ (revaluation) ไหม** ถ้ามี ต้องเพิ่มบัญชี
   และประเภทรายการรองรับ ถ้าไม่มี มูลค่าปัจจุบันในหน้าทรัพย์สิน
   จะเป็นแค่ตัวเลขอ้างอิง ไม่เข้างบดุล

### ไว้ค่อยก็ได้
6. **Management เข้าหน้าตั้งค่าผู้ใช้ไม่ได้** ตอนนี้เฉพาะ Super Admin
   ตามที่ลูกพี่เขียนว่า "Super Admin ทำได้ทุกอย่าง" และไม่ได้บอกว่า
   Management จัดการผู้ใช้ได้ — ถ้าอยากให้ได้ บอกผม แก้ไม่ยาก
7. **จะใช้โดเมนจริงไหม** หรือใช้ลิงก์ยาวๆ ของ Vercel ต่อ
   ถ้าจะใช้โดเมนจริง ต้องตั้งก่อนตั้ง key ของ Google Maps
   เพราะ key ต้องจำกัดโดเมน
8. **ไฟล์ยอดตั้งต้น** ลูกพี่บอกว่ารอก่อน — รอได้ครับ แต่ตัวเลขจริง
   จะเริ่มเดินได้ก็ต่อเมื่อมีไฟล์นี้

## 5. งานถัดไปที่ผมจะทำต่อ

1. ปิดชิ้นสิทธิ์ให้ผ่านตรวจ (กำลังทำ)
2. ต่อปุ่มบันทึกให้เขียนลง Supabase จริง — **ต้องเขียนผ่านคำสั่งเดียว
   ที่ลงหัวรายการกับบรรทัดบัญชีพร้อมกัน** ไม่ใช่สองคำขอ
   เพราะกลไกที่กันการแก้รายการที่ปิดแล้วจะปฏิเสธวิธีสองคำขอ
3. เพิ่มสถานะเปิด-ปิดของบัญชีธนาคารเข้าเครื่องยนต์ เพื่อกันการลงรายการใหม่
   เข้าบัญชีที่ปิดไปแล้ว (แต่ยังต้องกลับรายการเก่าได้)
4. สะสางไฟล์ migration ให้ตรงกับ DB จริง
5. ต่อไฟล์แนบเข้า Supabase Storage (ตอนนี้ยังเป็นชื่อไฟล์จำลอง)
