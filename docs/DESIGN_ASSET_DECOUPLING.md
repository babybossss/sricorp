# เชื่อม Asset Management กับ Ledger แบบไม่ติดล็อค

ลูกพี่เปลี่ยนใจ 06/10 — เอาแบบเชื่อมกันตั้งแต่แรก แต่ต้องไม่ติดล็อคและต่อยอดได้ระยะยาว
(แทนที่แผน "แยกกันก่อน" ใน D-081)

---

## ข้อสรุปสั้นที่สุด

> **เชื่อมด้วย "ข้อเสนอ" ไม่ใช่ "คำสั่ง" · เชื่อมทางเดียว ไม่ใช่สองทาง**
> **และเอาความเข้มงวดไว้ฝั่งเงิน ไม่ใช่ฝั่งทะเบียน**

สามข้อนี้ตอบคำว่า "ไม่ติดล็อค" ได้ครบทั้งสองความหมาย —
ล็อคตอนใช้งาน (คีย์เพิ่ม/ซื้อเข้าแล้วยาก) และล็อคตอนพัฒนา (แก้ทีหลังต้องรื้อ)

---

## 1 · ลูกศรชี้ทางเดียว

```
ทะเบียนทรัพย์ ──► ตัวแปล ──► lib/ledger ──► ฐานข้อมูล
      ▲                                        │
      └──────── อ่านยอดกลับมาแสดงเท่านั้น ◄─────┘
```

**ทะเบียนทรัพย์ไม่เคยสร้างบรรทัดบัญชีเอง** มันผลิตแค่ *เจตนา* ออกมาเป็นข้อมูลธรรมดา:

```ts
// src/lib/ledger/sources/types.ts
export type EntryIntent = {
  source: "asset_recurring" | "slip" | "import" | "schedule";
  sourceRef: string;        // กันสร้างซ้ำ
  ownerId: string;
  subCode: string;          // หมวดย่อยในตารางกฎ
  amount: number;
  docDate: string;
  assetId?: string;
  contactId?: string;
  bankAccountId?: string;
};

/** ที่เดียวในระบบที่รู้จักทั้งสองโลก */
export function intentToPosting(i: EntryIntent, resolve: Resolver): PostingInput;
```

**โมดูลทรัพย์ไม่รู้จักคำว่าเดบิตเครดิตเลย** และ `lib/ledger` ไม่ import อะไรจากโมดูลทรัพย์
ถ้าพรุ่งนี้ลบฟีเจอร์ทรัพย์ทิ้งทั้งก้อน `lib/ledger` ยังคอมไพล์ผ่าน

นี่คือสิ่งที่กันการติดล็อคตอนพัฒนา — ลูกศรชี้สองทางเมื่อไร แก้ฝั่งหนึ่งต้องแก้อีกฝั่งเสมอ

## 2 · เชื่อมแล้วได้ "ร่าง" ไม่ใช่ "รายการที่ลงแล้ว"

กฎเหล็กข้อ 6 อยู่แล้ว แต่ในบริบทนี้มันคือสิ่งที่กันการติดล็อคตอนใช้งาน:

- ร่างคือข้อเสนอ — ปฏิเสธได้ แก้ได้ ปล่อยไว้เฉยๆ ก็ได้
- ไม่มีอะไรที่ย้อนไม่ได้ เพราะยังไม่มีอะไรลงบัญชี
- **ทางคีย์มือยังอยู่ครบเหมือนเดิม** ระบบอัตโนมัติเป็นของที่เพิ่มเข้ามา ไม่ใช่ของที่มาแทน

ลูกพี่ยังคีย์เองได้ทุกเมื่อ ไม่ต้องรอระบบ และไม่ต้องลบของที่ระบบสร้างก่อน

## 3 · ความเข้มงวดอยู่ฝั่งเงิน ไม่ใช่ฝั่งทะเบียน

**นี่คือข้อที่ตอบความกังวลเรื่อง "คีย์เพิ่ม/ซื้อเข้าจะทำยากมาก" โดยตรง**

| | ขั้นต่ำที่ต้องมี | ที่เหลือ |
|---|---|---|
| **ลงทะเบียนทรัพย์** | ชื่อ · ชนิด · ประเภทการถือ · ผู้ถือ | เติมทีหลังได้ทั้งหมด — ราคาประเมิน โฉนด พิกัด ผู้เช่า สัญญา รายการประจำ |
| **ลงรายการเงิน** | ครบตามตารางกฎ ไม่มีข้อยกเว้น | — |

ทะเบียนเป็น**ข้อมูลอ้างอิงที่ดีขึ้นเรื่อยๆ** ซื้อทรัพย์มาวันนี้ ใส่แค่ชื่อกับชนิดก็บันทึกได้
พรุ่งนี้ได้โฉนดค่อยเติม อาทิตย์หน้าได้ผู้เช่าค่อยเติม

ที่คนมักทำผิดคือเอากติกาของฝั่งเงินไปใช้กับทะเบียนด้วย แล้วกลายเป็นว่า
**ซื้อทรัพย์มาแล้วลงระบบไม่ได้เพราะยังไม่มีเลขโฉนด** — ทะเบียนก็เลยว่างเปล่าตลอดกาล

## 4 · ไม่มีตัวเลขเงินสองที่

ทะเบียนทรัพย์**ห้ามเก็บยอดคงเหลือ** ไม่ว่ากรณีใด · เก็บได้แค่ข้อเท็จจริงกับแผน

ตัวเลขเงินทุกตัวบนหน้าทรัพย์คำนวณจาก ledger ตอนเปิดหน้า
ถ้าวันหนึ่งเก็บ "ยอดคงเหลือ" ลงแถวทรัพย์เมื่อไร สองฝั่งจะเริ่มไม่ตรงกัน
และจะติดล็อคอยู่กับการไล่กระทบยอดไปตลอด

## 5 · แหล่งที่สร้างรายการ แยกเป็นไฟล์ละแหล่ง

```
src/lib/ledger/sources/
  asset-recurring.ts     ← รายการประจำของทรัพย์
  slip.ts                ← อัพสลิปเป็นชุด
  opening-balance.ts     ← ยอดตั้งต้นจาก Excel
  contract-schedule.ts   ← งวดตามสัญญา
```

เพิ่มวิธีสร้างรายการแบบใหม่ = เพิ่มไฟล์ ไม่เคยแตะ engine (กฎเหล็กข้อ 4)
แต่ละไฟล์คืน `EntryIntent[]` เหมือนกันหมด — ตัวแปลตัวเดียวรับทุกแหล่ง

นี่คือเหตุผลที่ระยะยาว develop ต่อได้: LINE · OCR · API ธนาคาร
วันหน้าก็เป็นไฟล์อีกไฟล์ในโฟลเดอร์นี้

## 6 · ทุกร่างจำที่มาของตัวเอง

`source` + `source_ref` มีในสคีมาอยู่แล้ว · ต้องกรอกทุกครั้ง ไม่ใช่กรอกเมื่อนึกได้

ทำให้ตอบได้ว่า **"เดือนนี้อะไรที่ระบบสร้างเองบ้าง"** และ
**"ยกเลิกทุกอย่างที่มาจากแผนนี้"** — ถ้าไม่มี พลาดทีเดียวแล้วตามเก็บไม่ได้

## 7 · สวิตช์ยังอยู่ แต่กลับด้าน

```sql
assets.auto_post_enabled  boolean not null default true
```

**เชื่อมเป็นค่าตั้งต้น ปิดได้รายทรัพย์** — ต่างจากแผนเดิมที่ปิดเป็นค่าตั้งต้น

ลูกพี่ได้ทั้งสองอย่าง: ใช้งานได้เลยตั้งแต่วันแรก และถ้าทรัพย์ชิ้นไหนมีปัญหา
ปิดชิ้นนั้นชิ้นเดียวได้โดยไม่ต้องแก้โค้ดและไม่กระทบชิ้นอื่น

## 8 · หน้ากระทบยอดยังต้องมีเหมือนเดิม

การเชื่อมไม่ได้ทำให้ drift หายไป มันแค่**ย้ายที่มา** —
ลดการคีย์ซ้ำซ้อน แต่เพิ่มความเสี่ยงจากแผนที่ล้าสมัย
(ค่าเช่าขึ้นแล้วแต่แผนยังเป็นราคาเดิม · ผู้เช่าย้ายออกแต่ยังไม่ปิดสถานะ)

หน้าเทียบทะเบียน vs บัญชีคุม และ คาดการณ์ vs จริง ยังจำเป็นเท่าเดิม

---

## สิ่งที่เปลี่ยนจากแผนเดิม

| | แผนเดิม (D-081) | แผนนี้ |
|---|---|---|
| ค่าตั้งต้นของ auto | ปิด | **เปิด** |
| ลำดับ | แยก → กระทบยอด → เชื่อม | **เชื่อมเลย + กระทบยอดคู่กันไป** |
| สวิตช์รายทรัพย์ | มี | **มี (เหมือนเดิม)** |
| `asset_id` บนรายการ | ต้องมีตั้งแต่วันแรก | **เหมือนเดิม** |
| ความเข้มงวดของทะเบียน | ไม่ได้พูดถึง | **ผ่อนชัดเจน — ลงทะเบียนใช้แค่ 4 ช่อง** |

ข้อที่ไม่เปลี่ยนเลยคือ `asset_id` บนรายการเงิน — เป็นข้อเดียวที่ทำย้อนหลังไม่ได้
ไม่ว่าจะเลือกเชื่อมหรือแยก
