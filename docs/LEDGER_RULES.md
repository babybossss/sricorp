# กฎบัญชีของ SRI OS

เอกสารนี้คือสิ่งที่ `mace-windu` ใช้ตรวจ และเป็นที่มาของ `src/lib/rules/tx-rules.ts`
ถ้าโค้ดขัดกับเอกสารนี้ **เอกสารนี้ถูก** และโค้ดต้องแก้

---

## 1. Money Invariants — ห้าม override ทุกกรณี

ใช้กับทั้ง Corporate และ Personal บังคับที่ DB ไม่ใช่แค่ที่ application

1. **ทุก transaction สมดุล** — Σ debit = Σ credit
2. **ไม่มีเงินลอย** — ทุกการเคลื่อนไหวเงินสดผูก `bank_account_id` หรือกระเป๋าเงินสดที่มีตัวตน
3. **โอน/ข้าม owner มี 2 ขาเสมอ** — ขาออก + ขาเข้า ระบบสร้างคู่ให้
4. **ห้าม DELETE** — มีแต่ void/reverse ที่เห็นร่องรอย
5. **กระทบยอดธนาคารก่อนปิดเดือน** — ยอดในระบบ vs statement ต่อบัญชี ถ้าต่างแล้วหาไม่เจอ
   ปิดเดือนไม่ได้ ยกเว้น Personal ที่ลง "รายการปรับปรุงผลต่าง" พร้อมเหตุผล และต้องแสดงเป็นบรรทัดแยกใน P&L/CF
6. **Consolidated ตัด intercompany แล้ว** เงินสดรวม = ผลรวมยอดธนาคารทุกบัญชีเสมอ

## 2. ประเภทรายการ → ผลกระทบต่องบ

ตารางนี้คือความจริงเดียว โค้ดอยู่ที่ `src/lib/rules/tx-rules.ts`

| กลุ่ม | CF | P&L | ผูก Asset | หมายเหตุสำคัญ |
|---|---|---|---|---|
| **Income +** | Operating | ✓ | ตามแหล่ง | ค่าเช่า · ดอกเบี้ยรับ · ปันผลรับ · ค่าบริการ |
| **Expense −** | Operating | ✓ | optional | ซ่อมบำรุงที่ไม่ใช่ปรับปรุงใหญ่ |
| **Investing −** | Investing | ✗ | **บังคับ** | ซื้อทรัพย์ · **ปล่อยเงินขายฝาก/จำนอง/ให้กู้** · ซื้อหลักทรัพย์ · **ค่ารีโนเวท (capitalize)** |
| **Investing +** | Investing | เฉพาะ gain/loss | **บังคับ** | ขายทรัพย์ · **รับไถ่ถอน/คืนเงินต้น** |
| **Financing +** | Financing | ✗ | – | กู้ธนาคาร · กู้ยืมกรรมการ · **เพิ่มทุน (แยกจากเงินกู้)** · รับเงินมัดจำ |
| **Financing −** | Financing | เฉพาะดอกเบี้ย | – | คืนเงินต้น · จ่ายดอกเบี้ย · **จ่ายปันผล (ลดส่วนของเจ้าของ)** |
| **Transfer** | ไม่นับ | ✗ | – | โอนระหว่างบัญชีตัวเอง · ข้าม owner ต้องเลือกลักษณะ |

## 3. ห้าลงผิดที่เจอบ่อยที่สุด

เขียนไว้เพราะเคยผิดจริงใน Excel เดิม

| ทำผิดแบบนี้ | ที่ถูกคือ | ถ้าผิดจะเกิดอะไร |
|---|---|---|
| กู้เงินเพิ่มลงเป็น **รายได้** | Financing + (หนี้สินเพิ่ม) | P&L บวมเกินจริง หนี้สินหาย |
| คืนเงินต้นลงเป็น **ค่าใช้จ่าย** | ลดหนี้สินในงบดุล | P&L ติดลบเกินจริง หนี้สินไม่ลด |
| จ่ายปันผลลงเป็น **ค่าใช้จ่าย** | ลดส่วนของเจ้าของ | กำไรสุทธิผิด |
| ปล่อยกู้/ขายฝากลงเป็น **Financing −** | Investing − (ลูกหนี้เพิ่ม) | CF เพี้ยน แยกไม่ออกว่าเงินไปไหน |
| รับดอกเบี้ย + เงินต้นรวมเป็นก้อนเดียว | แยก: ดอกเบี้ย→Income · เงินต้น→Investing + | รายได้บวมเท่าเงินต้น |
| โอนเข้าบัญชีตัวเองนับเป็น **รายได้** | Transfer ไม่เข้า P&L | รายได้ซ้ำซ้อน |

## 4. Entity Policy

### Corporate (`corporate_strict`) — เข้ม 100% ห้าม override
- ต้องมี: วันที่เอกสาร · เลขที่เอกสาร · contact · หมวดจากผังที่อนุมัติ · **ไฟล์หลักฐาน**
- ห้ามหมวด "อื่นๆ" แบบไม่ระบุ
- post แล้วแก้ไม่ได้ → reverse + ลงใหม่
- ปิดงวดแล้วล็อกถาวร
- ข้าม owner ต้องระบุลักษณะ (ทดรอง / กู้ยืม / เพิ่มทุน / ปันผล) + สร้างขาอีกฝั่งอัตโนมัติ

### Personal (`personal_flexible`) — ยืดหยุ่นได้ แต่เงินห้ามหาย
override ได้ถ้าใส่เหตุผลและบันทึก audit:
- ไม่แนบหลักฐาน (ขึ้นเตือนใน Data health)
- ใช้หมวด "อื่นๆ" / ไม่ผูก contact
- แก้รายการที่ post แล้วในงวดที่ยังไม่ปิด (เบื้องหลังทำ reverse + ลงใหม่)
- ลงย้อนหลัง · เปิดงวดที่ปิดแล้ว (เฉพาะ Management)

**แต่ Money Invariants ข้อ 1–6 ห้ามละเมิดทั้งสองฝั่ง**

## 5. Pipeline — ไม่มีทางลัด

```
Source → draft_entries → Approve → transactions (posted) → Reports
```

- Automation ทุกตัวสร้างได้แค่ **draft** ยกเว้น mark-to-market ที่ลงใน `asset_valuations` (ไม่ใช่ transaction เงินสด)
- Management ข้ามขั้นอนุมัติได้ แต่ยังต้องมี audit log
- ไม่มีวงเงินอนุมัติ — อนุมัติจ่ายจริงเกิดที่ธนาคาร

---

## 6. เรื่องที่ยังต้องยืนยันกับผู้สอบบัญชี

อย่าตัดสินเองในโค้ด ให้ทำเป็น config แล้วรอคำตอบ

1. **Cost basis หลักทรัพย์**: MVP ใช้ Average cost — ต้องยืนยันว่าฝั่งบริษัทใช้ FIFO หรือ Average
2. ดอกเบี้ยขายฝาก/จำนองเกินเพดานตามกฎหมายหรือไม่
3. การแยกถือทรัพย์/รับรายได้ระหว่างบุคคลกับบริษัทต้องมีเหตุผลทางธุรกิจจริง
   ระบบมีรายงาน "รายได้ค่าบริการสะสม 12 เดือนต่อบุคคล" เตือนเมื่อใกล้เกณฑ์ VAT
   **ระบบเตือน ไม่ตัดสิน**
