## 2 · รูกลับรายการ — ตามที่ลูกพี่สั่ง "ปิดรูกลับรายการก่อนเลย"

เจอ **3 รู** ไม่ใช่ 1 รู

| | รู | ผลถ้าไม่ปิด |
|---|---|---|
| 1 | ไม่มีอะไรตรวจว่าใบกลับรายการสะท้อนต้นฉบับ + นิติบุคคลยกเว้นหลักฐานให้ใบ reverse | ตั้ง `source='reverse'` ชี้ไปใบเล็กๆ แล้ว **ลงเงินเท่าไหร่ก็ได้ ไม่ต้องแนบหลักฐาน** = override กติกาที่ห้าม override |
| 2 | ต้นฉบับ void ได้ขณะที่ใบกลับรายการยังนับอยู่ | สมุด **ผิดไป −ต้นฉบับ** คือผิดเท่าตัวของยอดเดิม |
| 3 | `trg_period_locked` เป็น `before insert` เท่านั้น | **void รายการในงวดที่ปิดแล้วได้** งบที่ยื่นสรรพากรไปแล้วเปลี่ยนเงียบๆ |

ยังไม่มีใครใช้ได้จริงเพราะหน้าจอยังไม่ต่อ DB แต่ต้องปิดก่อนเปิดใช้

### ต้องตัดสินใจก่อน — ผมตัดสินไปแล้ว **ลูกพี่ veto ได้**

`void` กับ `reverse` **ไม่มีเอกสารไหนเขียนว่าอันไหนใช้เมื่อไหร่** และคอมเมนต์ในโค้ด
ชวนให้ใช้ผิดทาง บันทึกเป็น **D-097** แล้ว:

| | `void` | `reverse` |
|---|---|---|
| ใช้เมื่อ | งวด**ยังไม่ปิด** | งวด**ปิดแล้ว** / ส่งงบไปแล้ว |
| ต้นฉบับ | → void ไม่นับในงบ | ยัง posted **นับต่อไป** |
| ใบกลับรายการ | ไม่มี | มี · วันที่ปัจจุบัน |
| งบเดือนเก่า | แก้ให้ถูก | **ไม่ขยับ** |

### ที่ทำเสร็จแล้วคืนนี้

**✅ ฝั่งเครื่องยนต์ — `buildReversal()`** (`src/lib/ledger/reversal.ts`)

จุดออกแบบที่สำคัญที่สุด: **สะท้อนบรรทัดที่เก็บไว้ ห้ามสร้างใหม่จากตารางกฎ**
เพราะตารางกฎเปลี่ยนได้ (เมื่อวานเพิ่ม 3 รหัสเข้าผังบัญชี) ถ้าสร้างใหม่จะได้คู่บัญชี
**ของวันนี้** ไม่ใช่ของที่ต้นฉบับใช้ปีก่อน → สองใบหักกันไม่หมด เหลือยอดค้างใน
บัญชีเก่าตลอดกาล **โดยที่งบยังดูสมดุล** (เพราะแต่ละใบสมดุลในตัว) = ไม่มีอะไรดังเตือน

และสะท้อนคือ **คัดลอกแล้วสลับข้าง ไม่มีการคำนวณ** → ไม่มีโอกาสปัดเศษเพี้ยนจากต้นฉบับ

มิติทุกตัวตามไปด้วย (ธนาคาร · ทรัพย์ · หมวดกระแสเงินสด) เพราะทิ้งตัวใดตัวหนึ่ง
งบรวมยังสมดุลแต่งบกระแสเงินสด/งบรายทรัพย์/ยอดตามบัญชีธนาคารเพี้ยน — หายาก

ปฏิเสธ ไม่เดา: ต้นฉบับ void แล้ว · กลับไปแล้ว · บรรทัดน้อยกว่า 2 · ไม่สมดุล ·
บรรทัดที่ไม่ใช่เดบิตหรือเครดิต · ไม่ใส่เหตุผล · ส่งซ้ำ · ข้ามผู้ถือมาขาเดียว

**20 เทสต์ · mutation 5 แบบทำให้แดงทุกแบบ** (ไม่สลับข้าง · ทิ้งมิติ · ถอดด่าน void ·
ถอดด่านครบคู่ · ถอดด่านสมดุล)

**✅ ฝั่งฐานข้อมูล — `20261009000000_reverse_integrity.sql`** ปิดทั้ง 3 รู

| ด่าน | ปิดรูไหน |
|---|---|
| `trg_reverse_mirrors_original` | 1 · **constraint trigger แบบเลื่อน** (ตอนลงหัวรายการ บรรทัดยังไม่เกิด) · **อ่านบรรทัดต้นฉบับจาก DB เอง** ไม่เชื่อค่าที่ผู้เรียกส่ง · `except all` สองทิศ เพื่อจับบรรทัดเกินที่สมดุลในตัวเอง |

**ผมรันเทสต์เองไม่เชื่อตามรายงาน**: harness **exit 0 · 281 assertion · 17 ไฟล์เทสต์**

**ด่านฝั่ง DB กับเครื่องยนต์เทียบคอลัมน์ชุดเดียวกันเป๊ะ** — ตรวจแล้ว ไม่ใช่สองฝ่ายตีความต่างกัน

## 2.5 · คำสั่งลูกพี่เรื่อง void — "ตัดออกจากงบ แต่มีให้เห็น" (D-098)

ตรงกับ D-097 ฝั่ง `void` พอดี **และทำให้เจอของที่ขาด 2 อย่าง**

**1 · ไม่มีคอลัมน์บันทึกการ void เลย** — ไม่มี `voided_at` · `voided_by` · `void_reason`
→ รายการที่ยกเลิกจะเห็นได้จริง แต่เห็นเป็น **ผีที่ไม่มีคำอธิบาย**
ผู้สอบบัญชีถามว่า "ทำไมเดือนนั้นหายไปหนึ่งใบ" แล้วตอบไม่ได้ = ทำลายเหตุผลของการเก็บไว้ให้เห็น

> ผมตัดสินว่า **`void_reason` บังคับทุกผู้ถือ** ไม่ใช่แค่นิติบุคคล · ลูกพี่ veto ได้

**2 · ยังไม่มี view ของสมุดเลย** (มีแต่ของทรัพย์/สัญญา 3 ตัว)
→ ตอนเขียนรายงาน **คนเขียนต้องจำเองว่าต้องกรอง void ออก** ซึ่งเป็นรูปแบบเดิมของบั๊กที่เจอซ้ำที่สุด

> ผมตัดสินว่าทำให้เป็น**เรื่องโครงสร้าง ไม่ใช่เรื่องความจำ**:
> `revoke select on transactions` จาก `authenticated` แล้วให้สิทธิ์เฉพาะ
> `v_ledger_posted` (แหล่งเดียวของงบ · ไม่มี void) และ `v_ledger_voided` (หน้ารายการที่ยกเลิก)
> → เขียนรายงานที่ลืมกรอง void **ไม่ได้** เพราะเข้าถึงตารางดิบไม่ได้ตั้งแต่แรก

**"ไปเก็บอีกที่" = แยกด้วย view ไม่ใช่ย้ายแถว** — ย้ายแถวจริงคือ delete + insert
ซึ่งละเมิดกฎเหล็กข้อ 1 ที่ trigger บังคับอยู่ · ทำให้ `reverses_id` ขาด (ประวัติว่าใบไหน
กลับใบไหนหายทันที) · และ `audit_log` จะชี้ไปของที่ไม่มี

**ยังไม่ได้ทำ ~2–3 ชม.** (คอลัมน์ + กันแก้ย้อนหลัง + สอง view + สลับ grant + เทสต์)

## 3 · ขั้น 1 พร้อมจบในคำสั่งเดียว — `scripts/apply-migrations.sh`

เขียนและทดสอบกับ Postgres ในเครื่องแล้ว แทนเครื่องมือ MCP ที่ **timeout ~40% ของครั้งที่เรียก**
แบบสุ่ม (วัดแล้ว ไม่เกี่ยวขนาดไฟล์ — `drop function` บรรทัดเดียวก็ timeout)

ปลอดภัยไว้แล้ว: dry-run เป็นค่าเริ่มต้น · ไฟล์ละ transaction · หยุดที่ไฟล์แรกที่พัง ·
**พิมพ์ error จริงไม่สรุป** · รับรหัสผ่านจาก env เท่านั้น ไม่รับเป็น argument (argument ไปอยู่ใน `ps`)

**แก้บั๊กที่แพงที่สุดไปด้วย**: harness เลื่อนไฟล์ seed ไว้ท้ายสุดโดยตั้งใจ แต่สคริปต์ผม
เรียงตามชื่อ → **สิ่งที่เราทดสอบกับสิ่งที่เรา apply เป็นคนละลำดับ**
แก้ด้วย `supabase/migration-order.txt` ที่ทั้งสองฝ่ายอ่านไฟล์เดียวกัน

> ข้อจำกัดที่ต้องพูดตรงๆ: ทดสอบจาก DB เปล่าแล้ว **9 ไฟล์พัง** เพราะไฟล์ที่เพิ่มคอลัมน์
> `txn_types` ใส่ check constraint ที่แถว seed ตอนนั้นยังละเมิด แล้วพังต่อเป็นทอดๆ
> อาการนี้เป็นของการ replay จาก DB เปล่า **ของจริงมีคอลัมน์พวกนั้นแล้ว**
> แต่ **ผมยืนยันกับของจริงไม่ได้จนมี `SRI_DB_URL`** จึงให้มันหยุดที่ไฟล์แรกที่พัง
