# URL และ Domain — สถานะจริงและขั้นตอน

> ตรวจจาก Vercel API ตรงๆ 9 ต.ค. (ไม่ใช่เขียนจากความจำ)

## สถานะวันนี้

| | |
|---|---|
| Vercel project | `sri-os` (team `thanakorns`) · framework Next.js · Node 24.x |
| Domain ที่ผูกอยู่ | **`sri-os.vercel.app` เท่านั้น** (ของแถมจาก Vercel) · ยังไม่มี domain ของตัวเอง |
| URL ที่ใช้ดูงานตอนนี้ | `https://sri-os-git-claude-blissful-euler-54m3md-thanakorns.vercel.app` |
| Production | **ยังไม่เคย deploy** (`live: false` · deploy ล่าสุดเป็น preview) เพราะเราไม่เคย push ขึ้น `main` |
| รหัสผ่านหน้าเว็บ | ปิด |
| Vercel SSO | **เปิด** แต่ตั้งไว้แบบ `all_except_custom_domains` |

## 🔴 เรื่องสำคัญที่สุด — ลำดับมีผลต่อความปลอดภัย

**`ssoProtection.deploymentType = "all_except_custom_domains"`**

แปลว่า ตอนนี้ URL `*.vercel.app` ทุกตัว **ต้องล็อกอิน Vercel ก่อนเข้า** (ปลอดภัยอยู่)
แต่ **วินาทีที่ผูก domain ของตัวเอง domain นั้นจะเปิดสู่อินเทอร์เน็ตทันที**
ไม่มี SSO ของ Vercel กั้นอีก เหลือแต่ระบบล็อกอินของแอปเองเป็นด่านเดียว

**และระบบล็อกอินของแอปตอนนี้ยังตรวจสิทธิ์ใครไม่ได้เลย** เพราะตาราง roles
ยังไม่ apply ขึ้น DB จริง (ขั้น 1) → ทุกหน้าขึ้น "ตรวจสิทธิ์ไม่สำเร็จ"

→ **ผูก domain ตอนนี้ = เอาข้อมูลการเงินของครอบครัวไปวางบน URL สาธารณะ
ที่กำแพงล็อกอินยืนยันตัวตนใครไม่ได้**

**ลำดับที่ถูกต้อง**
1. ขั้น 1 (apply migration) → ตาราง roles ขึ้น DB
2. สร้างบัญชีผู้ใช้จริง + เปิด Google provider
3. **ทดสอบว่าคนที่ไม่มีบัญชีเข้าไม่ได้จริง** บน URL `.vercel.app` (ที่ยังมี SSO กั้นสองชั้น)
4. ค่อยผูก domain

ถ้าอยากผูก domain ก่อนจริงๆ ต้องเปลี่ยน SSO เป็น **`all`** (ครอบ custom domain ด้วย)
ซึ่งจะทำให้ทุกคนต้องมีบัญชี Vercel ของทีมด้วย — ปลอดภัยแต่ใช้งานยากสำหรับผู้สูงอายุ

## ขั้นตอนผูก domain (ทำได้ ~30 นาที + รอ DNS)

### 1 · เลือกและซื้อ domain
ซื้อที่ไหนก็ได้ (Vercel · Cloudflare · GoDaddy · ของไทยเช่น Z.com)
**ซื้อที่ Vercel ง่ายสุด** เพราะไม่ต้องตั้ง DNS เอง (แต่แพงกว่าเล็กน้อย)

ชื่อที่เหมาะกับระบบภายในครอบครัว — ไม่ควรเดาได้ง่ายว่าเป็นระบบการเงิน
และควรใช้ subdomain แยก เช่น `os.<ชื่อโดเมน>.com` เพื่อให้เว็บบริษัท (ถ้ามีวันหลัง)
อยู่คนละที่กับระบบภายใน

### 2 · เพิ่มใน Vercel
Vercel → project `sri-os` → Settings → Domains → Add

### 3 · ตั้ง DNS ที่ผู้ขาย domain
Vercel จะบอกค่าที่ต้องใส่ · ปกติคือ

| ประเภท | ใช้เมื่อ | ค่า |
|---|---|---|
| `A` | โดเมนหลัก (`example.com`) | `76.76.21.21` |
| `CNAME` | subdomain (`os.example.com`) | `cname.vercel-dns.com` |

**ให้ยึดค่าที่หน้า Vercel บอกเป็นหลัก** ไม่ใช่ค่าในตารางนี้ เพราะ Vercel เปลี่ยนได้

รอ DNS กระจาย **5 นาที – 48 ชม.** (ปกติไม่เกินชั่วโมง) · ใบรับรอง HTTPS Vercel ออกให้เอง

### 4 · ชี้ production ให้ถูก branch — **ข้อนี้ลืมกันบ่อย**
Domain จะชี้ไปที่ **production** ซึ่งตอนนี้ผูกกับ `main` และ **ยังไม่เคย deploy เลย**
งานทั้งหมดอยู่บน `claude/blissful-euler-54m3md`

มีสองทาง **ต้องเลือก**
- **(ก) merge ขึ้น `main`** แล้วให้ production มาจาก `main` ตามปกติ — สะอาดกว่าในระยะยาว
  และ `main` จะเป็นตัวแทน "ของที่ใช้งานจริง"
- **(ข) เปลี่ยน Production Branch** ใน Vercel → Settings → Git เป็น branch นี้ —
  เร็วกว่าแต่ทำให้ไม่มีเส้นแบ่งระหว่าง "กำลังพัฒนา" กับ "ใช้งานจริง"

**ผมแนะนำ (ก)** เพราะพอมีคนใช้งานจริงแล้ว ลูกพี่จะต้องมีที่ให้ทดลองของใหม่
โดยไม่กระทบคนที่กำลังคีย์ข้อมูลอยู่

### 5 · อัปเดตค่าที่ผูกกับ URL — **ไม่ทำแล้วล็อกอินพัง**
1. **Supabase** → Authentication → URL Configuration
   - Site URL = `https://<domain ใหม่>`
   - Redirect URLs เพิ่ม `https://<domain ใหม่>/auth/callback`
2. **Google Cloud Console** (OAuth client ที่ใช้ล็อกอิน)
   - Authorized JavaScript origins เพิ่ม `https://<domain ใหม่>`
   - Authorized redirect URIs เพิ่ม URL callback ของ Supabase
3. **Vercel env** ถ้ามีตัวแปรที่เก็บ URL ของเว็บ ต้องอัปเดตด้วย

**เก็บ URL เดิมไว้ในรายการด้วย** อย่าลบ ไม่งั้นลิงก์ที่ส่งกันไว้แล้วพัง

## สรุปสิ่งที่ลูกพี่ต้องตัดสินใจ

1. **ชื่อ domain** (ซื้อแล้วหรือยัง · ถ้ายัง จะซื้อที่ไหน)
2. **production มาจาก `main` หรือ branch นี้** (ผมแนะนำ `main`)
3. **SSO**: เปิดเฉพาะ `.vercel.app` ตามเดิม (แล้วรอให้ auth ของแอปใช้ได้ก่อนผูก domain)
   หรือเปลี่ยนเป็น `all` เพื่อผูก domain ได้เลยโดยยังมี Vercel กั้น
